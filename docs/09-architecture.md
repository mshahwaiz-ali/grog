# Grog Software Architecture — Canonical Implementation Contract

**Updated:** 2026-11-07  
**Status:** This is the **approved implementation architecture baseline when the user tells Grok to start**. The strategy's experimental numeric parameters and live execution assumptions retain their research/OPEN statuses in the owning documents. **R0 (M00–M08) is implemented against this contract** (as-built notes in §2.1; acceptance evidence in [14](14-r0-acceptance-audit.md)); offline M09-A/H adapter components are implemented on fixtures while M09-B remains blocked.

**Goal:** local, deterministic, low-maintenance Python Gold (XAUUSD) research/terminal software. Only improve measurable manual trade selection and monitoring. No LLM/agent runtime, wallet, account dashboard, copy trading, remote SaaS, automatic broker execution, or GitHub Actions.

This file owns module layout, interfaces, schemas, data persistence, command surfaces, runtime modes, failure semantics and dependency selection. **No duplicate indicator formulas, trading strategy thresholds or precise UI layout** here: [03](03-market-data.md), [04](04-analysis-engine.md), [05](05-strategies.md), [06](06-signals-and-scoring.md), [07](07-risk-and-monitoring.md), [02](02-workflows-and-ux.md) respectively are authoritative. Tests are [08](08-validation.md); implementation order [10](10-roadmap.md); approvals [11](11-decisions.md).

## 1. Architectural decisions

- **Python:** target Python **3.11** for initial reproducibility on Ubuntu; verify selected libraries support it; no system-wide Python replacement.
- **Package tool:** `uv` project + `pyproject.toml`, `uv.lock` committed. Use `uv sync --locked` after lock exists; dependency versions come from an actually resolved lockfile, not invented package pins.
- **TUI:** `textual` (Rich renderables as supported by Textual), style in a single `.tcss`; retained as fallback. **The analysis engine must never import Textual, Rich or TUI-specific state.** Local Qt Widgets desktop migration approved (§12).
- **Local operations DB:** Python `sqlite3`, migrations in versioned SQL files, WAL mode, foreign keys and proper transactions; no PostgreSQL, web server or cloud.
- **Raw market data:** immutable, checksummed **local files** divided by source/time batch; metadata and journal in SQLite. Small synthetic fixtures in tests; do not commit large/private third-party datasets.
- **Calculation numerics:** `decimal.Decimal` for quote/contract prices and money, UTC integer epoch milliseconds for event-time; named explicit rounding policies per broker tick size. Indicator EMA/ATR recurrence can use tested high-precision Decimal and round only at final executable prices. Avoid float-vs-decimal nondeterminism between replay runs.
- **Pure domain engine:** processing one normalized market event + previous state yields deterministic next state/events. No network, filesystem, sleep or real clock hidden inside indicators/strategy rules. Inject a Clock and DataHealthPolicy.
- **Threading model:** one process, a controlled ingestion/replay producer and one ordered **market-event consumer**. UI subscribes to state snapshots; high-frequency updates are coalesced for **view only**, never dropped from engine inputs. No premature microservices, brokers, sockets, brokers' order APIs, automated remote monitors.
- **Main branch only**, direct normal Git commits; GitHub Actions disabled/not required. All code/test execution local to Grog, never on `erp.omchouse.com` or other production systems.

Official framework/package guidance: https://github.com/Textualize/textual ; https://docs.astral.sh/uv/guides/projects/ ; https://packaging.python.org/en/latest/guides/writing-pyproject-toml/ ; https://docs.pytest.org/ ; https://docs.astral.sh/ruff/

## 3. Canonical domain contracts — data types, fields, invariants

Use frozen typed Python `dataclass(slots=True, frozen=True)` for immutable market/domain events, and explicit constructors. Prefer small immutable records; don't pass arbitrary untyped dictionaries between core modules.

### 3.1 NormalizedQuote (market data owner: docs/03)

| Field | Type | Invariant |
| --- | --- | --- |
| `source_id` | nonempty str | Identifies a single platform/dataset; never synthetic mixture |
| `canonical_symbol` | literal `XAUUSD` | Internal name, independent of broker symbol suffix |
| `raw_symbol` | str | Exactly as supplied by feed |
| `provider_time_ms` | int | UTC provider ms (if unavailable, reject for initial replay input rather than infer silently) |
| `received_time_ms` | int | UTC time Grog first ingested event; for offline fixture may be set by explicit recorded fixture policy |
| `ingest_order` | int | Unique increasing order **within source import/runtime stream**; same-ms distinct events survive |
| `bid`, `ask` | Decimal | Both >0, `ask>=bid` |
| `source_origin` | Enum | `SYNTHETIC`, `HISTORICAL`, `BACKFILL`, `REFERENCE_LIVE` |
| `source_event_key` | str | Stable event identity from batch checksum+row ordinal or provider cursor + index |
| `flags` | immutable set[str] | E.g. carried ASK/BID side, quality facts |

**Never use source timestamp alone as unique ID.** Quote object includes full source metadata. Original raw input is retained in source file; normalized CSV/JSON serialization uses canonical UTC numbers and exact decimal string, not floats.

### 3.2 FinalizedBar (market data owner: docs/03)

`bar_id=(source_id,timeframe,start_utc_ms)`, `timeframe in {M1,M5,M15,H1}`, `start_ms,end_ms` half-open UTC, `open_bid,high_bid,low_bid,close_bid` Decimal, `open_ask,high_ask,low_ask,close_ask` Decimal if complete, `tick_count` int, `closed_at_received_ms`, `available_at_ms`, `quality` enum (`COMPLETE`, `GAPPED`, `INVALID`).

- A completed bar is usable only if its end was reached and a valid quote finalized it at a genuinely known time. Empty bars are **missing** rather than fabricated OHLC by repeating previous close.
- Bid bars drive [04] indicator/pivot computations; ask extrema support executable short stops.
- Missing side or interval gap => `GAPPED/INVALID`; cannot silently join into reliable strategy signal.
- Engine uses `available_at_ms <= decision_received_time_ms`, never backdates the signal to a historical candle's mathematical end.

### 3.3 AnalysisContext (analysis owner: docs/04)

`source_id, decision_time_ms, last_confirmed_h1_id, last_confirmed_m15_id, last_confirmed_m5_id, h1_bias {UP,DOWN,NEUTRAL,UNKNOWN}, m15_context {SUPPORTIVE,CORRECTIVE,OPPOSING,UNKNOWN}, ema_values, atr_values, confirmed_pivots, relevant_level_ids, quality_flags, calculation_version`.

Indicators emit `UNKNOWN` if warm-up insufficient/zero ATR/invalid bars. Never replace missing values with a flattering zero or threshold PASS.

### 3.4 StrategyCandidate (owner: docs/05)

`candidate_id` deterministic from source, strategy version, side and frozen pivot pair IDs; `strategy_id=S1`, `side=BUY|SELL`, `state`, `pair_id`, `impulse_L/H` and confirmation timestamps, `P`, `depth`, `last_closed_m5_id`, `first_detected_ms`, `last_changed_ms`, `observed_reason_codes`, `parameter_set_hash`, `source_origin`.

Only one FORMING pair per side in provisional S1; newer pair causes explicit `SUPERSEDED`; never mutate original frozen pair. Detect event time and confirmed availability separated.

### 3.5 SignalRecord (owner: docs/06)

`signal_id` derived deterministically from candidate and **first valid trigger bar**, `candidate_id`, `strategy_version`, `side`, `original_source_id`, `first_ready_ms`, `original_bid,original_ask`, `E0,SL0,TP1,TP2`, `frozen_atr`, `entry_low,entry_high`, `expiry_ms`, `execution_fidelity`, `original_risk_price`, `estimated_cost_model_id_or_none`, `evidence_snapshot_json`, `state`.

**Immutability rule:** all `original_*` and frozen plan fields are never overwritten; current quote/eligibility overlay is a **separate read model or event**, not mutation of old signal history. A unique candidate/pair may issue **at most one READY** in S1 baseline.

### 3.6 ManualPosition (owner: docs/07)

`position_id`, `signal_id_or_none` (off-plan allowed with explicit label), `mode`, `side`, `entry_fill_time_ms`, `entry_recorded_ms`, `actual_fill_price`, `original_lots`, `remaining_lots`, `initial_risk_currency_or_unknown`, `current_sl/tp_reported_or_none`, `broker_or_none`, `fees_paid_or_unknown`, `state=MONITORING|RECONCILIATION_REQUIRED|CLOSED`.

Every partial/modify/close is an append-only `PositionEvent` with stable action ID, event/record time, price, quantity, fees and reason; remaining quantity cannot be negative. **This is local journal data, not an account/wallet or broker order.** Position creation/update MUST require an explicit local user confirmation, never price-touch auto-execution.

**Single direction of dependencies:** adapters → market_data → analysis → strategies → signals/risk → journal/replay → UI (UI calls explicit safe local journal command port only). Domain and analysis never import adapters/UI. No circular imports.

## 5. Runtime profiles — implement offline first

`REPLAY`: uses a virtual deterministic UTC clock (next quote timestamp) and historical/synthetic source; no broker connection. All READY/events are labeled **SIMULATED**. Never connect to real broker or notify as if a live trading recommendation.

`REFERENCE_LIVE` (future): reads MT5 demo/source quotes via read-only exporter; source metadata tagged REFERENCE. Positions may be **manually recorded**, but without chosen actual execution broker fees/contracts the UI displays **INDICATIVE** and no invented monetary P/L or position sizing. Require measured heartbeat/quality thresholds before showing fresh live signal.

`EXECUTION_VERIFIED` (future readiness state, not initial build): only when instrument metadata, execution conventions and user-reported fill observations for actual venue are validated. It remains **manual execution**, not a trading API. No automatic mode switch merely because an MT5 demo is connected.

The eventual broker is **NOT required** for `REPLAY` or for researching price structure, indicators or hypothetical S1. Source and execution venue may differ; never silently relabel reference results as broker-verified.

### 5.1 M09 read-only MT5 reference adapter — implementation contract

Smallest design that satisfies [03 §8](03-market-data.md) without touching the pure engine. Status: **offline Python side implemented (M09-A) and integrity-hardened (M09-H, H1–H4, 2026-10-31); MQL5 exporter source revised but still uncompiled and untested in MT5; no terminal, Wine, broker account or network connection used** ([10 §9](10-roadmap.md)). Every statement below about MT5 runtime behavior is the documented intent of the source, **not observed behavior** — real byte output, tick-time convention, offsets, session tables and history depth are UNVERIFIED until M09-B.

```text
MT5 terminal (Wine, demo server, one XAUUSD symbol)
  └─ mql5/GrogReferenceExporter.mq5   read-only: timer-driven CopyTicksRange polling + heartbeat
        │ append-only rotated text files  (transport GROG-MT5-REF/1)
        ▼
  adapters/mt5_reference/format.py  parse + validate one line → typed record or RecordError(code)
  adapters/mt5_reference/feed.py    ReferenceNormalizer (UTC, side carry-forward, dedup, order)
                                    ReferenceReader (rotation, complete lines only, durable cursor)
  live/session.py                   ReferenceSession: LinkMonitor (heartbeat, injectable clock)
                                    + the unchanged S1ResearchPipeline (bars → analysis → S1 → signals)
        ▼
  CLI `grog reference-status` (read-only, never advances the cursor)
  `grog ui --mode reference` → NOT_CONFIGURED (no config) / NOT_AVAILABLE (view wiring is M09-B)
```

`adapters/` and `live/` are outside the replay engine code hash (§2.1), so REPLAY run IDs and outputs are unchanged by M09.

**Exporter behavior (authored, not yet run).** Inputs are validated at start (`source_id` in the Grog safe set, positive timer/chunk/warm-up/rotation values); invalid input or an unreadable/corrupt watermark file → `INIT_FAILED` with a message (never a silent 20-day re-warm-up). On start it writes `M`, then opens one catch-up block from its saved watermark (first start only: `InpWarmupDays`, default 20 days — whether the broker keeps that much tick history is **UNVERIFIED**, M09-B). The catch-up is **timer-driven**: each timer event processes at most a few `InpChunkMinutes` windows and then writes `H`, so heartbeats continue during a long catch-up. `CopyTicksRange` is inclusive at both ends, so adjacent windows are `[a, b−1]`, `[b, c−1]`, … (no overlap); only the block start re-delivers the watermark millisecond. A window that fails (return < 0 or a set `_LastError`) is retried a small number of times (engineering default 3 attempts, 500 ms apart — not a trading threshold); on exhaustion the exporter writes a `G` gap record for that window and continues — the gap is explicit, never silent. Then every `InpTimerMs` (default 1 s) it polls `CopyTicksRange(COPY_TICKS_INFO)` from the last exported ms, skipping the ticks of that ms it already wrote (the live stream never re-delivers; a failed live poll is simply retried from the same watermark), and writes `H`. `OnTick` is intentionally unused (events coalesce). A reconnect (`TERMINAL_CONNECTED` false→true) opens a new catch-up block from the watermark. Every write is checked (bytes written = bytes requested); a short or failed write stops the exporter's output and the watermark is **never** advanced past data that was not fully written. The watermark is saved atomically (temp file + `FileMove` replace). Session OPEN/CLOSED comes from `SymbolInfoSessionQuote`, including sessions that wrap past midnight and the previous day's wrapping session (broker session tables UNVERIFIED). Heartbeat time has 1 s resolution (`TimeTradeServer()`), so a heartbeat threshold must exceed 1 s.

**One source.** One exporter instance = one `source_id`, one demo server, one raw symbol mapped to `XAUUSD`. No aggregation, no second broker.

**Transport `GROG-MT5-REF/1`.** Directory `reference.exporter_dir`; files `<source_id>__<session start UTC YYYYMMDDTHHMMSSZ>__<part 000001>.grogref`, processed in lexical file-name order. **Bytes:** UTF-8, each line terminated by exactly one LF (0x0A), comma-separated, no quoting. The exporter writes binary bytes (`FILE_BIN`, `StringToCharArray(…, CP_UTF8)`) — MQL5 text mode (`FILE_TXT`) would emit CR LF and `FILE_ANSI` the system code page, both of which the strict parser rejects (`BAD_LINE_END`, `BAD_ENCODING`). File names are unique: the exporter never reopens an existing name (a same-second restart advances the stamp) and never truncates a file. A line is consumed only when its LF exists (a torn last line is never parsed). Field 2 of every record is a per-file line sequence starting at 1 and increasing by exactly 1; a jump is `TRANSPORT_SEQ_GAP`, an **integrity fault** (below).

| Record | Fields | Meaning |
| --- | --- | --- |
| `M` | `M,1,GROG-MT5-REF/1,<producer>,<source_id>,<server>,<raw_symbol>,<digits>,<server_offset_s>,<exporter_version>` | must be line 1 of every file; `producer` = `MQL5_EXPORTER` or `FIXTURE` (fixtures are always displayed FIXTURE / SIMULATED, never as live reference prices) |
| `T` | `T,<seq>,<mode L\|B>,<time_msc>,<bid>,<ask>,<flags>` | one `MqlTick`: `time_msc` exactly as MT5 reports (trade-server clock, ms), prices with ≤ `digits` decimals, `flags` the integer `MqlTick.flags`; `L` = live poll, `B` = catch-up (`CopyTicksRange`) |
| `H` | `H,<seq>,<server_time_msc>,<connected 0\|1>,<session OPEN\|CLOSED\|UNKNOWN>,<server_offset_s>` | timer heartbeat (exporter default every 1 s), also written when no tick arrives |
| `B` / `E` | `B,<seq>,<from_msc>` · `E,<seq>,<to_msc>,<count>` | catch-up block begin/end; `from_msc` inclusive (re-delivers the watermark ms), windows inside a block contiguous and non-overlapping; `count` = number of `T` lines between `B` and `E` (mismatch → `CATCHUP_COUNT_MISMATCH` fault; `B` inside an open block or `E` without `B` → `CATCHUP_SEQUENCE` fault) |
| `G` | `G,<seq>,<from_msc>,<to_msc>,<error>` | irrecoverable gap: a catch-up window the exporter could not read after its retries → `SOURCE_GAP` fault |
| `Z` | `Z,<seq>,<next file name or ->` | clean end of file (rotation or shutdown) |

**Per-file metadata.** Each file must start with a valid `M` (line 1). A file whose `M` is missing, malformed or names another source has **no** metadata: its records are rejected (`NO_META`) and the file raises `META_INVALID` / `SOURCE_MISMATCH` faults — metadata is never inherited from an earlier file. A later `M` that changes `producer`, `server`, `raw_symbol` or `digits` is a source switch: rejected with a `META_CHANGED` fault (a different source needs its own `source_id`).

**Exact values and the time boundary (UNVERIFIED).** Prices are parsed to `Decimal` from the text (never via float); more decimals than `digits` → `PRICE_PRECISION`. `provider_time_ms = time_msc − server_offset_s × 1000`, with the offset from this file's `M` or a later `H`. **This conversion is a declared boundary, not a verified fact:** the exporter can only report the *current* `TimeTradeServer() − TimeGMT()`, MT5 offers no historical offset, and whether `time_msc` is trade-server time is itself unobserved. Therefore: (1) a reported offset that differs from the one in force is an `OFFSET_CHANGED` fault (history converted with two offsets — e.g. across DST — blocks READY); (2) catch-up ticks older than the first offset observation of the current exporter session are flagged `OFFSET_ASSUMED`; (3) the session reports `TIME_BASIS_UNVERIFIED` as an actionable blocker until an authorized MT5 observation (M09-B) verifies the convention. `received_time_ms` = Grog's clock when the line was read (true availability), forced non-decreasing. A tick whose provider time is ahead of its receipt is flagged `FUTURE_TIME` and is never LIVE; the tolerance `max_future_skew_ms` is **OPEN (unset)** — while unset every READY is blocked (`FUTURE_SKEW_TOLERANCE_UNSET`); if a tolerance is later declared, a tick beyond it is rejected with a `FUTURE_TIME` fault.

**Price sides.** `flags & 2` = BID changed, `flags & 4` = ASK changed (MT5 `TICK_FLAG_BID/ASK`). An unchanged side may be empty/0 and is carried forward from the last accepted value; the quote carries `BID_CHANGED` / `ASK_CHANGED` and `ASK_CARRIED` / `BID_CARRIED` flags. A side flagged as changed must be a positive price. A tick before both sides are known → `SIDE_UNKNOWN` (held out, counted). Ticks with neither flag (last/volume only) → `NON_QUOTE` (ignored, counted). `ask < bid` → `CROSSED` (quarantined). A side whose flag says *unchanged* but whose supplied value differs from the last accepted value is `SIDE_INCONSISTENT`: the quote keeps the supplied value, carries the flag and raises a fault (never silently trusted; what MT5 `COPY_TICKS_INFO` supplies for unchanged sides is UNVERIFIED).

**Identity and dedup.** `source_event_key = <source_id>:<time_msc>:<bid>:<ask>:<flags>:<n>`. Only a catch-up block re-delivers (its inclusive start); the live stream never does. So for a `B`-mode tick `n` is the occurrence index of that content within that ms **inside the block** — an identical re-delivery gets the same key and is dropped as `DUPLICATE`; for an `L`-mode tick `n` continues the occurrence count of the accepted stream for that ms, so a genuine identical same-ms tick after a block is kept. Distinct same-ms ticks always get distinct keys. A `B`-mode tick older than the last accepted `provider_time_ms` is re-delivered history → `OUT_OF_ORDER` (counted, dropped); an `L`-mode tick older than it is an `OUT_OF_ORDER` **fault**. Recent keys (bounded window) are part of the cursor.

**Durable cursor.** `<state_dir>/reference/<source_id>.cursor.json`, written atomically (temp file, fsync, rename, directory fsync) only after the records up to it were handed to the session: file name, byte offset, expected next line sequence, a fingerprint of the file's first line, last bid/ask, offset, last accepted time, occurrence counters, recent keys and latched faults. It is written only when the position moved, at most every 10 000 lines or 10 s of Grog clock (engineering constants; a crash re-reads at most that tail, which is then BACKFILL behind the startup fence). Restart resumes exactly at the cursor: no tick is skipped and none is re-emitted. A cursor that cannot be parsed → `CURSOR_CORRUPT` error with a next step (never silently reset). One writer per cursor: a session that commits holds an exclusive `flock` on `<source_id>.lock`; a second writer is refused (`CURSOR_LOCKED`); `reference-status` never commits and takes no lock. The cursor's file vanishing before its `Z` → `CURSOR_FILE_MISSING` fault; the file shrinking below the cursor offset → `FILE_TRUNCATED` fault; a different first line under the same name → `FILE_REPLACED` fault. No new SQLite table is needed.

**Bounded ingestion.** Files are streamed in 1 MiB blocks and events are handed to the session one at a time, so memory does not grow with file size (engineering constants, not thresholds). Throughput and RSS are recorded in [08 §15.6](08-validation.md).

**Integrity faults.** `TRANSPORT_SEQ_GAP`, `FILE_ENDED_WITHOUT_Z`, `PARTIAL_LINE_DISCARDED`, any malformed line (`BAD_*`, `UNKNOWN_RECORD`, `PRICE_PRECISION`, `INVALID_PRICE`), `META_INVALID`, `SOURCE_MISMATCH`, `META_CHANGED`, `OFFSET_CHANGED`, `CATCHUP_COUNT_MISMATCH`, `CATCHUP_SEQUENCE`, `SOURCE_GAP`, `SIDE_INCONSISTENT`, live `OUT_OF_ORDER`, `FUTURE_TIME` (beyond a declared tolerance), `CURSOR_FILE_MISSING`, `FILE_TRUNCATED`, `FILE_REPLACED`. A fault is counted, latched in the cursor state with its file/line, puts the link in `INTEGRITY_FAULT` and blocks every actionable READY. It is never cleared automatically; the recovery procedure after an integrity fault is OPEN (to be defined from M09-B evidence; [11 §15](11-decisions.md)). Quarantine-only codes that do not latch: `DUPLICATE`, catch-up `OUT_OF_ORDER`, `NON_QUOTE`, `SIDE_UNKNOWN`, `CROSSED`.

**Backfill vs live.** A quote is **LIVE-eligible** only if it is mode `L`, outside a `B…E` block, **and** `received − provider ≤ live.max_quote_age_ms`. Everything else (catch-up, backlog read after a Grog restart, late lines) is **BACKFILL**: it advances bars/analysis causally, but any READY issued while processing it is recorded as *historical* and is never shown as actionable. With `max_quote_age_ms` unset nothing is LIVE-eligible. On start the session first replays retained files up to the cursor as history (warm-up). Warm-up history is **RECONSTRUCTED**: its bars carry the restart time as availability (the original receipt times are not persisted), its quotes are flagged `RECONSTRUCTED`, and any READY from it is historical. **Startup fence:** everything read by the first poll after start (the restart backlog) is BACKFILL, so a READY the previous process may already have shown is never replayed as a new opportunity.

**Link and feed state (timer-driven).** `ReferenceSession.poll()` is called from a timer (UI/CLI) and evaluates at the injected clock's now, so staleness is found **without waiting for another tick**:

| Link state | Condition (first match) |
| --- | --- |
| `NOT_CONFIGURED` | no `[reference]` config / exporter dir |
| `NO_DATA` | configured, no record read yet |
| `INTEGRITY_FAULT` | a latched integrity fault (reason = first fault code) |
| `DISCONNECTED` | latest heartbeat reports `connected=0` |
| `OFFLINE` | heartbeat age > `reference.max_heartbeat_age_ms`, where age = max(now − Grog receive time, now − heartbeat server time in UTC) — a backlog of old heartbeat lines can never look live |
| `UNKNOWN` | `max_heartbeat_age_ms` unset (`HEARTBEAT_THRESHOLD_UNSET`) |
| `CATCHING_UP` | inside an open `B…E` block |
| `MARKET_CLOSED` | heartbeat session `CLOSED` (or a declared closure) |
| `LIVE` | otherwise |

Feed health is the existing `assess_feed` evaluated at clock now (FRESH/STALE/DEGRADED/CLOSED/UNKNOWN). **Actionable** = READY issued on a LIVE-eligible quote outside the startup fence, still READY, unblocked and unexpired, **and** no actionable blocker: link not `LIVE`, feed not `FRESH`, `INTEGRITY_FAULT`, `FIXTURE_SIMULATED`, `TIME_BASIS_UNVERIFIED`, `FUTURE_SKEW_TOLERANCE_UNSET`. The status lists the blockers. A FIXTURE producer's would-be-actionable READY appears only in a separate **simulated** lane, never as actionable. Reference prices are labeled `REFERENCE · INDICATIVE` (fixture producer: `FIXTURE · SIMULATED`), never broker-verified; P/L stays UNKNOWN.

**Safety.** Prices never create journal records (the session has no journal dependency). Neither side contains order/position/account mutation calls (`OrderSend`, `OrderSendAsync`, `CTrade`, `PositionClose`, `OrderModify`, …); a test scans both sources and checks the session's public API. REPLAY code paths are unchanged.

**Contract metadata.** The reference policy maps no price step (the contract tick size is not verified), so the engine reports `CONTRACT_UNDEFINED` and issues **no** READY from a real reference feed until the owner declares a verified tick size for that symbol — by design, nothing is guessed from `digits`.

**Config (all unset by default).** `[reference] source_id`, `exporter_dir`, `max_heartbeat_age_ms`; freshness still from `[live] max_quote_age_ms`, `max_first_postclose_delay_ms`. The future-skew tolerance and the time-basis verification are deliberately **not** configurable yet (OPEN; blockers stay on). Thresholds must be measured on the authorized demo feed ([10 §9](10-roadmap.md)). `grog ui --mode reference` stays NOT_AVAILABLE for real operation until the M09-B source-validation gate.

## 6. Simple offline import format v1 — publish fixture and parser

Canonical CSV header (UTF-8, comma, LF, no timezone ambiguity):

```csv
provider_time_utc_ms,received_time_utc_ms,bid,ask
1793440000000,1793440000000,4000.00,4000.20
1793440000300,1793440000310,4000.01,4000.21
```

The above numbers are **illustrative synthetic data**. The importer requires `--source-id` and `--origin SYNTHETIC|HISTORICAL` flags; it assigns stable `source_event_key=sha256(file_bytes)+"#"+row_ordinal` and increasing `ingest_order`. It may allow an optional extra source sequence field **only when explicitly documented**; no hidden dialect guessing, coercing NaN, guessing seconds vs milliseconds, or treating invalid rows as zero. Source metadata supplies symbol alias; default canonical instrument is XAUUSD for this project.

For a file with invalid header, invalid UTC ms, crossed quote, negative price, inconsistent source or missing column: importer fails with structured line number/reason and **does not partially commit the batch** by default. An explicit `--quarantine-invalid` future option requires its own tests; don't silently skip a subset and call the import complete.

Native vendor formats, bid/ask side-update flags, out-of-order streams and compression are separate adapter-specific transformations which must preserve the normalized contract, not add hidden exceptions to the canonical CSV parser.

## 10. Error handling and recovery

| Failure | Engine response | Operator response |
| --- | --- | --- |
| Malformed tick/negative quote | Reject/quarantine, never invent price | Source code + row/time/field |
| Duplicate identical imported batch | Idempotent no-op | "Already imported" with checksum |
| Multiple different ticks same ms | Keep stable original stream order | No duplicate suppression by timestamp |
| Out-of-order/gapped source | Mark data quality and affected bar UNKNOWN | Feed health degraded; no new actionable signal |
| Data import interrupted | Atomic file+catalog logic and restart recovery | Clear retry without corruption |
| Bad broker tick metadata | Monetary sizing unavailable | Explicit missing field, not default to 1 lot |
| No historical warm-up | Context UNKNOWN; no S1 READY | "Need N valid closed bars" |
| Reconnect and backfill | Rebuild reliable context, not retrospective live READY | "Backfill processed; live proposals suspended until fresh" |
| Storage DB locked/fails | Fail closed for journaling, retry bounded or graceful exit | "Position record NOT saved", don't claim it was |
| UI crash/restart | Journal + signal state restored from durable events | Open manual positions require reconciliation |
| No broker chosen | REPLAY works; REFERENCE requires MT5 demo source | No demand for actual trading broker |
| Unknown event calendar | Show unknown; don't claim no news | Policy-specific safety warning |
| Conflicting candidates | Display uncertainty, suppress duplicate risk | Never auto-pick on unsupported score |
| Same bar hits stop/TP in OHLC | Indeterminate without tick order | No optimistic win |

**Crash recovery:** processed input watermark and all signal/journal state changes committed consistently; replay input after watermark with idempotent event IDs; restore persisted positions as RECONCILIATION_REQUIRED until operator verifies. No future-lookahead due to delayed data repair.

### 13.2 Runtime data-flow diagram (one-way, local-only)

```text
EXISTING IMPORTED SOURCE / CHECKSUMS / CONFIG
        |
        v
Store.open_read_only -> load_source_quotes -> ReplaySession
                       (replay-owned thread: causal pre-roll + ordered quote events)
        |                  |                      |
        |                  +-> every quote -> TouchTracker <- immutable current positions
        |                  +-> S1ResearchPipeline -> signals/events/health/bars
        |                                            |
        +-----------------> detached UiFrame <-------+
                          (generation, sequence, UTC, source, exact Decimals,
                           immutable context/statuses/events, no SQLite objects)
                                       |
                            queued Qt signal, <=4 UI redraws/s
                                       v
                          GUI THREAD / Qt widgets
             Overview | Signals | Positions | Journal | Diagnostics
                                       ^
                     immutable position/journal/overlay replies
                                       |
                         JOURNAL OWNER WORKER
           Store.open -> PositionJournal.restore_on_startup
           signal_actions / positions / decisions / events
                                       ^
                   explicit validated and confirmed local commands
                                       |
                         GUI action controller
     pause-acknowledge replay -> re-read current signal/source and claim
     -> preview -> confirm -> revalidate -> submit stable action_id
     -> BEGIN IMMEDIATE/validated PositionJournal transaction -> result
```

A frame must carry `source_id`, `source_origin`, `fidelity`, config/strategy identifiers (as available), **monotonically increasing market sequence** and **source generation**. UI caches may replace a *display frame* from the same generation when redrawing; they must never drop, coalesce or merge engine inputs, journal writes, touch observations, eligibility changes, or signal/journal event records. The UI's "Latest snapshot" is **not** a historical event log. On every changed frame, key rows by full immutable IDs, preserve selection/scroll position and show a changed/expired detail state rather than resurrecting rows. Source switching increments generation, drains/invalidates queued old frames, leaves in-flight confirmed journal writes committed and visible only in their correct source context, and requires explicit source acknowledgment.

**Thread topology:** Qt GUI/main thread exclusively owns QWidgets, QAbstractItemModel objects and dialog lifecycle. One dedicated replay QThread owns the `ReplaySession` and its `TouchTracker`, processing a bounded work slice then servicing control requests; it alone appends `quote_observers` and orders ticks. One serialized journal QThread **creates its own** writable `Store` and `PositionJournal` (never inherit a sqlite connection from another thread), owns migration/restore/commands/read operations and closes its connection before thread exit. Use Qt queued signals/slots and a small read-model/command coordinator; don't introduce multiprocessing, network RPC, shared mutable Qt state or generic event-bus framework.

**Bounded work and delivery:** At 50/500 events per second use existing `advance(elapsed_s)`; FAST remains the existing 5000-events-per-call budget, yielding to the worker event loop between calls. **Pause handshake and forms:** On opening a REPLAY edit form, send "pause" command and **wait for replay-worker acknowledgement with cursor/generation and source ID** via a nonblocking Qt flow before enabling edit/submit. Now the replay snapshot is stable; no spontaneous expiry/clock drift while modal is open. Any queued stale frame is ignored by generation+sequence. Keep replay paused when form closes. Before save, request a new current engine/overlay read, ensure the exact target ID still exists and is unclaimed, and construct `EntryRequest` with **fresh** `signal_ready`, `signal_blocked`, source, `known_clock_ms` and matched original `PlanRef`; never accept a raw flag copied from a dialog opened earlier. ### 13.3 Journal and signal correctness boundary

`PositionJournal.record_entry(req)` and `record_skip` make their SQLite writes atomic and enforce the **first operator claim per signal** and duplicate-action-ID semantics. They do **not** query the replay engine to prove `signal_ready`; that is the caller's duty. The desktop coordinator must therefore prevent forged/currently stale ON_PLAN state and preserve `PlanRef.from_record` immutable values. Position fills, timestamps, fee/contract unknowns, gross R and mark freshness come from existing journal/domain functions, not Qt arithmetic. Journal handlers convert `JournalError` into **NOT SAVED** + code + possible recovery; a retry of an uncertain commit uses the *same* action ID and exact payload, allowing the domain's idempotency check to say `created=False` without a second event. A changed payload needs an intentionally new action ID after new preview and confirmation. Keep the action ID private to the form/request; never treat window redraw as a new operator action.

Run a `TouchTracker` on each relevant quote for currently monitored locally recorded positions only, matching `source_id` and quote time; any `STOP`, `TP1`, `TARGET` hit is **TOUCHED — execution unconfirmed**. An in-memory touch from the current session is *not* a durable broker fill or a historical observation after restart unless backed by an existing durable event. Avoid inventing a "TP1 approaching" distance while its threshold remains OPEN. If a Journal command changes remaining quantity or stop/target, update the replay worker's tracked immutable position list before resuming replay. Risk, R, fee and price-side math remain in [07](07-risk-and-monitoring.md), implemented by existing domain code.

The **Journal screen is a provenance-aware union, not a new database table**: (a) SQLite `position_events` and `signal_decisions` via `PositionJournal`, and (b) in-memory `pipeline.signals.events` and S1 events from replay, with source/mode/strategy ID. Durable research runs/results are separately stored by `ResearchStore`; do not automatically insert all UI replay events into operator journal or imply that session history survives restart without a deterministic replay/reconstruction. Historical pre-roll events remain historical. Query/display may page/virtualize without changing ordering, event retention or idempotency; if existing read methods materialize too much, add a separately tested *read-only* service-level pagination/query method rather than SQL in Qt. No delete/edit/correction migration is authorized by desktop design.

**Permissions:** single local operator only; no login roles, broker credentials, cloud identity or external account linking. In REPLAY with writable local state, offer explicit operator-confirmed journal commands. In read-only/no-source/error state, expose only source-safe read functionality and disabled local writes with reasons. `REFERENCE_LIVE` active trading UI remains M09-B gated even if its **diagnostics read model** exists. No call graph from desktop to broker order placement or file exporter start.
